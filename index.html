# 01 · Verifiable

Public code, rejections first

Three of the five public repositories, all with CI on Python 3.11, 3.12 and 3.13. Each one states what it refused to do, what goes in and comes out, and where to check the claim. The other two, both about AI agents, are in orchestration.

cota-parlamentar

Public

Reproducible analysis of the Chamber of Deputies expense allowance: 209,066 entries for 2025.

Rejected
Ranking deputies by amount spent. The allowance varies by state to cover airfare, so that ranking measures distance from Brasília. A test fails if anyone adds such a query.
Contract
Official public file in; six SQL answers on DuckDB and a CI-regenerated report out, with the deputy's CPF dropped at load.
Evidence
70 tests, 100% coverage. Found outside the docs: the expenses API returns HTTP 200 with an empty list for every deputy; 937 entries belong to party leadership.

coletor

Public

Web scraper driven by a YAML description of what to collect.

Rejected
Getting around blocks with proxies, captcha solving or a forged browser. Of the stores measured, one returned 403, one 503, two render only after JavaScript. The target came from that measurement.
Contract
YAML config in; CSV or Excel out, after reading robots.txt and honoring Crawl-delay. An item missing a required field is dropped and reported, never written blank.
Evidence
155 tests, 100% coverage, suite runs against saved pages with no network.

botautomatic

Public

Browser automation runner for flows described in YAML.

Rejected
Mass messaging on social networks, the most common use for this kind of bot: it breaks third-party terms and every layout change. Also rejected: testing the real Selenium driver in CI.
Contract
YAML flow in; validated as a whole before any browser opens, then run with secrets from environment variables, retry with backoff, and --dry-run.
Evidence
79 tests. Selenium sits behind a six-method interface, so the runner is tested against an in-memory driver; 100% coverage outside the real driver.

# 02 · System

Aurum MTO

Private · method only

Algorithmic trading research & execution · Python · running continuously on a demo account

End-to-end platform: data collection, feature engineering, temporal validation with transaction costs, and a live execution daemon under risk control.

In financial time series it is trivial to produce a backtest that is beautiful and false. The only defense is deciding the acceptance criterion before seeing the result.

Validation protocol

  • Walk-forward analysis with temporal embargo, to prevent leakage across folds
  • Untouched out-of-sample holdout, reserved before any model selection
  • 1-SE rule for threshold selection, instead of maximizing the metric
  • Feature-group ablation, to isolate real contribution per block
  • Sensitivity and drift analysis across out-of-sample periods
  • Mandatory baseline comparison: no model accepted on absolute accuracy

Execution engineering

  • Daemon with signed PID ownership, stale-PID recovery, watchdog
  • Idempotent order reconciliation against broker positions, pending orders and history: no duplicate submission on restart or partial failure
  • Fail-closed on every ambiguity: corrupted state, inconsistent journal, out-of-band spread, or failed margin validation halts trading
  • Circuit breaker for terminal disconnection
  • Exposure arbitration serializing decisions across competing strategies, under an aggregate cap
  • Heartbeat, structured journal, alerting

# 03 · System

Faceless video channel

Private · name withheld

Automated content production pipeline · Python · over 20 videos published

Research, licensed media acquisition and auditing, narration, rendering, publication packaging. The repository versions knowledge rather than media: strategy, decisions, and the reasoning behind each change, so a format change can be compared, audited and reverted.

Governance

Eight operating procedures encapsulated as versioned, auto-triggering skills that chain by contract. Alongside them, written invariants, each one born from a documented failure: never edit a derived file when a generator exists; publication requires explicit per-upload approval, never inherited; explicit paths on every commit; stop and report factual errors rather than silently patching them.

Chained gates, in order

Multiple providers behind a canonical abstraction, per-source adapters, auto-refill when a segment runs short. Every asset passes:

  1. LicenseRejects NC/ND
  2. ProvenanceExcludes AI-generated material, including from sources that mix it in without disclosure
  3. TechnicalLandscape, minimum resolution
  4. SubjectThe source title must name what the segment is about
  5. DiversityPrevents visual repetition within a segment

Hash-based deduplication, rate-limit backoff, per-asset license manifest.

The open question, stated as open. The current format wins on click-through and collapses on average watch time against the previous one. Sample is small and the numbers conflict between sources, so no format change was made. Next step: per-second retention from the primary source, after the assisted tool produced conflicting figures twice.

# 04 · Orchestration

Orchestrating agents, with a ruler that can say no

Two public repositories where the agents are not the product: the rules around them are. One fixes who audits whom and refuses to run when that independence collapses; the other measures what a model extracts against a golden set checked by hand, and fails the build below the line.

orchestrating-independent-code-audits

Public

A process skill plus a Python bridge that runs a code audit across independent agents.

Rejected
The agent that wrote the code approving it, and an approval that outlives the commit it was given for. Who plays each role is chosen on first use and written to a file; the bridge refuses a run where the implementer also audits.
Contract
In: the chosen bindings and a commit. Out: each bound auditor called in phase order, read-only, with the verdict pinned to the commit SHA. Every auditor is checked for a live session before the audit starts; one signed out stops the run with AUDITOR_NOT_READY instead of a silent pass.
Evidence
90 tests, 94% coverage, CI on 3.11–3.13. The README separates what the bridge enforces with a test from what is only a rule in the skill text.
what is enforced → CI runs →

extrato-contratos

Public

Extracts contract notices from municipal official gazettes and measures the result against a golden set checked by hand.

Rejected
Calling a prompt good without a ruler. Also rejected: retrying until it passes, and publishing a number the model invented — an extracted amount or tax ID has to appear in the source text, or the record is dropped.
Contract
In: the gazette text. Out: one strict-schema record per notice, or a stated reason it was dropped. The model sits behind an adapter, and the suite reads recorded answers: no test calls a model, spends or touches the network.
Evidence
Over 13 real notices: 93.7% accuracy per field, 95.4% on the fields that change the meaning, for US$ 0.25. 68 tests, 97% coverage, and CI fails the run below 95% on those fields and 90% overall.
the measurement → the limits →

What this does not prove. The bridge enforces the rules that have a test; the rest of the process lives in the skill text and depends on whoever runs it. The golden set covers one municipality on one day, and one model. Neither repository has been run by a team other than mine.

# 05 · Method & limits

How these were built

All of them were built by orchestrating AI coding agents, with my role being architect and reviewer: defining safety invariants first, encoding architecture contracts as automated tests, and reviewing every decision against them. The gain is not typing speed; it is exploring more alternatives and discarding the bad ones earlier. What I don't delegate is the criterion: what gets accepted, what gets cut, and why.

What this does not prove

No production deployment with real capital. No cloud infrastructure and no containers: the two larger systems run locally on Windows. CI exists on the five public repositories, and it runs tests; nothing is deployed from it. No code reviewed by another engineer, no deep learning, no data at scale.

My professional background so far is in corporate health, not software. I'm in the first semester of a Systems Analysis and Development degree, and all of this was built alongside full-time work.

What I'm looking for is the context I haven't had in engineering: a team, review from someone other than myself, and priorities that come from outside my own head.
